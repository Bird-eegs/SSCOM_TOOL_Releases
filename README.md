# SSCOM TOOL V1.21

基于 **Python 3.10+、Tkinter/ttk 和 pyserial** 的 Windows 串口调试工具。窗口标题为 `SSCOM TOOL V1.21`。本版改为选择语言后直接切换，并修复扩展指令行发送按钮快速连点时后续点击被双击事件吞掉的问题。上方是尽量占满可用空间的接收区，底部为整合串口参数的发送工作区，右侧扩展栏可随时展开或隐藏。

参考已有 Python 工程的后台线程、队列和 PyInstaller 打包方式，界面与业务代码独立实现；运行时不依赖参考工程。工程不使用 C#、WinForms 或 Qt。

## 当前功能

- 串口枚举与刷新；自定义波特率、5～8 数据位、校验位、停止位、DTR / RTS，无流控。
- 文本 / HEX 发送，UTF-8 / ASCII / GBK 编码，追加无 / CRLF / CR / LF 结束符。
- 接收文本 / HEX 显示、时间戳、发送记录、自动滚动、清空和导出窗口日志。
- 接收区搜索默认显示，不抢占输入焦点；顶部搜索按钮或 Ctrl+F 可再次打开，框选接收区文字后按Ctrl+F直接匹配选区。支持匹配计数、上下跳转、大小写和全词匹配，随新增内容更新高亮。
- 文本 / HEX 可即时切换已有收发历史，保留原始字节；「样式 → 字体样式」设置接收区字体、字形、字号及颜色，支持 Ctrl+鼠标滚轮缩放。
- 收发不显示方向前缀；接收字符默认为黑色，可自定义；启用「显示发送」时发送回显为紫色 `#8000ff`。复选框使用加粗勾号。
- RX / TX 字节计数与清零。
- 主要按钮、下拉框、复选框及编辑对话框控件悬停后显示用途说明，延时由 `tooltip.py` 的 `delay` 设置；离开或点击后隐藏，禁用控件也可查看说明。提示框跟随控件所在显示器定位，在屏幕边缘调整位置，不再按主屏坐标限制。
- 顶部「语言」菜单选择六种界面语言，直接生效，不弹出切换确认框；滚轮不切换语言。
- 命名指令表的新建、切换、保存、导入、导出及整表删除；默认表受保护。指令支持新增、双击编辑、删除、排序及单条发送。
- 首次启动扩展默认隐藏；发送区标题行按钮或 F8 快速切换，隐藏后保留指令、勾选状态和选择位置。退出时记录窗口尺寸、最大化状态及扩展栏宽度和显示状态。
- 勾选指令顺序发送或循环发送；每条指令独立设置 HEX、结束符和发送后间隔。
- 定时发送与停止共用一个按钮，运行中再次点击或按 Esc 停止。
- 点击主「发送」按钮、按 Ctrl+Enter 或退出 APP 时保存指定参数；配置与预设支持手动 JSON 导入 / 导出。
- 演示回环：原样返回发送字节，完全不访问硬件。

## 启动

双击 `run.bat`，或在 PowerShell 中：

```powershell
.\.venv\Scripts\python.exe main.py

# 无硬件测试
.\.venv\Scripts\python.exe main.py --demo

# 将运行配置保存在工程目录内
.\.venv\Scripts\python.exe main.py --config .local\profile.json
```

本机已创建 `.venv`，复用现有 Python 3.12 环境中的 pyserial 3.5，没有下载安装 Qt，也没有更改系统默认的 Python 2.7。

在其他电脑准备环境：

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe main.py
```

需要使用包含 Tcl/Tk 的 Python 发行版；标准 Windows Python 安装程序可提供 Tkinter。`run.bat` 会检查 Python 版本、Tkinter 和 pyserial，并优先使用项目的 `.venv`，不会自动联网安装依赖。也可用环境变量 `SSCOM_PYTHON` 指定 Python 解释器的绝对路径。

## 使用

1. 在底部「发送工作区」选择真实 COM 口及参数，再点击「打开串口」。没有硬件时可选「演示回环」。普通启动不会自动连接真实设备。
2. 在发送工作区输入内容，点击发送或按 `Ctrl+Enter`。光标留在发送输入框时，Ctrl+Enter仅发送一次，不插入换行、不改变输入内容；普通Enter仍可换行。勾选「以HEX发送」会自动转换现有文本，例如 `A00` → `41 30 30`；取消勾选会按当前编码转回文本。ASCII 字符转成相应的 ASCII 十六进制字节值，中文等字符按所选 UTF-8 / GBK 编码转换。HEX 输入支持 `AA 55 00 FF`、`AA5500FF` 或 `0xAA,0x55`，遇到无效字符或单个半字节会拒绝发送。
3. **结束符会额外追加，HEX 模式同样如此。** 例如 `AA 55` + CRLF 实际发送 `AA 55 0D 0A`；不需要追加时选「无」。发送按钮下方显示包含结束符的字节数。
4. 点击发送区标题行浅黄色的「扩展」或按 F8 展开右侧预设栏。单击「指令内容」和「间隔ms」输入框可直接修改；双击指令内容打开「编辑预设指令」。点击该行凸起的名称按钮单独发送，不受勾选状态影响。示例命令只是可编辑模板，需按设备实际协议调整。
5. 在扩展中勾选多条指令，点击底部「发送」。取消「循环」时执行一轮；勾选时持续循环，可用「停止发送」停止，或关闭搜索后按 Esc 停止。只执行当前表中勾选的非空指令；空内容及仅含空格、制表符或换行的行自动跳过，文本与HEX行均适用，跳过的行不发送结束符、不产生额外等待。若勾选项全为空，不启动发送并提示至少勾选一条非空指令；非空指令中的HEX等参数错误仍会阻止启动，避免只执行一部分错误批次。「全选」可勾选全部指令，再次点击取消全选。
6. 定时 / 顺序发送启动前会验证全部待发内容，并对本次发送做快照。间隔范围为 **1～3600000 ms**，初始默认 **1000 ms**。间隔从上次写入完成后计算。停止后不再安排下一次发送，已经交给串口的写入无法撤回。
7. 扩展中的 JSON 导入添加一张指令表，不修改串口参数；文件菜单仍保留完整配置导入，需要先断开串口并确认替换。当前不解析 SSCOM 原版 INI。

## 多指令表与悬停说明

「扩展」抬头同行为可输入下拉框，文字始终居中：单击输入区修改当前表名，按Enter或移开焦点确认；点击下拉箭头选择其他表后立即切换。名称须非空且不与其他表重复，改名后点击「保存」写入磁盘。各表未保存的编辑保留在当前会话中。

扩展表格搜索和两行表格操作说明已移除，相关用途保留在悬停提示中。抬头下一行先显示粗体「指令表操作：」，然后为「新建、保存、导入、导出、删除」；五个按钮继续缩小且等宽，中文常规布局约48像素，面板变窄时提示文字与按钮分行，并按可用空间换行，保证全部可见。下方指令框顶部为加粗的短按钮「+、-、↑、↓」，整组居中，随面板宽度调整，空间不足时同样换行；分别用于新增、删除、上移和下移。已移除「编辑」「复制」按钮，双击指令内容仍可打开完整编辑框。工具栏边框为3像素，指令内容框边框仍为1像素；各行紧密相接，只保留1像素分割线。

「删除」针对当前整张指令表，确认框会显示表名。确认后原子保存更新后的表库、删除该表的全部行并切回默认表；取消不改变数据，写入失败则保留原表及尚未修正的输入。默认表的删除按钮禁用，自动发送运行中也会禁用整表删除。独立导出的JSON文件不受影响。

默认表身份保存为表库的 `default_table` 字段，默认表改名后仍不可删除；旧表库缺少该字段时，将原有第一张表认作默认表，保留其内容。单表导入不会替换默认表身份。整表删除会立即保存整个表库（包括当前会话的其他表改动），无需再点击保存。

表格默认只显示「选、指令内容、发送」三列。「循环」后新增「格式」「结尾」「间隔ms」三个显示复选框，默认不勾选；勾选后显示对应列，取消后隐藏，各列独立控制，顺序固定为「格式、结尾、间隔ms」。开关仅影响当前会话中的显示，隐藏时各行参数和未完成的输入保留，发送仍按各行原有设置执行；查看或编辑隐藏参数时也可双击指令内容打开完整编辑框。

勾选显示列时，直接从「指令内容」列分配宽度；取消后对应宽度归还指令内容。栏目总宽度随当前视口重算，正常面板宽度下无需横向拖动即可看到新增列。面板缩放时也会重排输入框与按钮。

「指令内容」与显示后的「间隔ms」为可单击编辑的输入框，修改立即保留在当前会话，点击保存后写入磁盘；双击指令内容可打开完整编辑框。间隔无效时输入框显示红框，保存、切表和发送前会提示修正，Esc可恢复最近有效值；滚动不会丢弃尚未修正的输入。

原「名称」与「操作」合并为凸起的发送按钮，位于指令内容之后，列宽固定95像素，文字统一为黑色。按钮显示自定义名称；名称仅在「编辑预设指令」窗口中修改。未命名时显示当前排列序号，移动、删除后按新顺序显示；已有配置中的自定义名称保留。每行只有这一个发送按钮。底部「全选/取消」已改为短按钮「全选」，「发送勾选项」改为短按钮「发送」；这两个按钮和「循环、格式、结尾、间隔ms」按六项控件的实际尺寸限制面板最小宽度，确保始终处于同一行且互不覆盖。V1.18使用画布统一绘制可见行，点击编辑时复用一个真实输入框。

点击「新建」弹出「新建指令表」对话框，填写名称，并可设置以下初始值：

| 项目 | 默认值与范围 |
| --- | --- |
| 指令表名称 | 必填，1～64字符，同名不重复。 |
| 预设条数 | 默认共50条，包含前2条查询模板，其余为空白；可设置0～500条。 |
| 格式 | 文本；可选HEX，查询模板也会转换为对应HEX。 |
| 结尾 | CRLF。 |
| 间隔ms | 100，范围1～3600000。 |
| 勾选参与顺序/循环发送 | 默认不勾选，包括模板行。 |

「确认」新建并切换到该表，不发送指令；「取消」保留原表。空白行可以保存为占位，顺序/循环发送时自动跳过；点击该行按钮单独发送前仍须填写内容。新建及新增最多至500行；旧版最多1000行的已有配置仍能导入读取。自动发送期间会禁用指令表切换与编辑，避免运行过程中更换表格。

「保存」将**全部指令表及当前选择**原子写入全局配置旁的独立文件，默认位于 **EXE 同目录的 `profile.tables.json`**。使用 `--config .local\profile.json` 时对应 `.local\profile.tables.json`。下次启动恢复已保存表格；未保存时数量旁显示「未保存」，退出时可选择保存、放弃改动或取消退出。初次未发现指令表库时，从原配置预设或默认模板建立「默认指令表」。

旧完整配置中的自定义预设会在首次保存全局参数前迁移到指令表库，避免旧配置改为只保存参数后丢失原指令。迁移保留原内容，新编辑仍通过「保存」写入。

扩展中的「导出」只导出当前表，包含表名、各行内容、勾选、格式、结尾及间隔；「导入」支持该JSON格式及旧完整配置中的预设。同名导入会自动附加编号，现有表格保留，串口参数不变。导入后点击「保存」纳入本机指令表库。文件菜单中的完整配置导入/导出针对全局参数和当前表，不包含其他表。

界面已移除独立的大抬头和顶部串口设置区域；串口、波特率、数据位、校验位、停止位、编码、DTR / RTS 均合并在发送工作区。窗口宽度不足时参数会自动换行。隐藏预设栏后，收发显示区使用全部宽度；拖动显示区与发送区之间的分隔条可调整高度。「定时发送」启动后变成「停止发送」，即使扩展栏隐藏，也能通过同一个按钮停止定时或多指令循环。

「清空」「保存日志」「扩展」位于「发送工作区」标题同一行，整组按钮已左移，使「保存日志」的右边缘对齐输入区右边缘。「清空」保持青色底、白色文字；普通按钮采用浅灰底，「扩展」使用浅黄色底和较短宽度。

串口开关位于发送工作区下方参数行的最左侧，直接排列在串口选择框之前，已移除独立的「串口」文字标签。打开后按钮显示红色的「关闭串口」；断开后恢复「打开串口」。

已经打开的设备被拔出或驱动暂时出错时，APP 保持串口打开状态和「关闭串口」按钮，状态栏显示「等待设备恢复」。发送与串口参数编辑暂时禁用，定时 / 顺序发送停止，尚未发送的指令作废。同一 COM 口恢复后，后台按原参数重新连接；自动发送不会自行重启。等待期间仍可点击「关闭串口」或退出。已失效的底层驱动句柄会释放，APP 保留的是连接意图和界面状态；初次打开串口失败时仍返回未连接状态。

串口选择框收起时仅显示 `COM101` 等串口名；点击下拉按钮展开加宽列表后显示 `COM101 · USB-SERIAL CH340 (COM101)` 等完整设备信息。选择后恢复短名称，保存配置和连接设备均使用实际串口名。演示项收起时显示「演示回环」。Windows 下根据选择框所在显示器的工作区定位弹出列表，支持副屏与负坐标屏幕；靠近右侧或底部时调整位置，保持在当前屏幕内，不再按主屏尺寸定位。

指令输入框外部宽度固定为 **850 像素**，高度随发送区高度调整。其右侧第一行为「发送」「结束符选择」「结束符」「以HEX发送」，第二行为「定时发送 / 停止发送」「间隔数值」「ms」，下方显示「字节数 · 含结束符」。输入区与控制区保留 10 像素间距。窗口最小宽度按输入框、工具栏与右侧控件的实际尺寸计算，保证完整显示；窗口变宽时输入框仍保持 850 像素。

顶部按「文件、串口、样式、语言、帮助、搜索」排列，其后间隔70像素顺序显示「HEX 显示、时间戳、显示发送、自动滚动、显示格式」；空间不足时显示选项自动换行。五个菜单按钮已隐藏默认下拉箭头，点击仍展开对应菜单。已去掉「收发工作区」标题和原接收区工具栏，接收区填满空出的空间；鼠标框选接收区文字时，选区底色及失焦颜色与发送输入区一致。

搜索条默认打开在接收区右上角，不抢占启动时的输入焦点。高度为 **46像素**，输入区加宽到 **200像素**，字体、图标和按钮同步放大；整体宽度按计数及按钮的实际宽度计算，比原260像素搜索条加长。匹配数变长时搜索条随之加宽，空间不足时限制在接收区内。依次为输入框、`x/y`匹配计数、↑、↓、`Aa`大小写匹配、带下划线的`ab`全词匹配、×关闭。普通匹配使用浅蓝底，当前匹配使用浅黄底；顺序按当前显示内容从头到尾排列，到末尾或开头后循环跳转。支持Enter/F3向下、Shift+Enter/Shift+F3向上；Esc先关闭搜索框，搜索关闭后Esc停止发送。关闭搜索清除高亮并保留接收内容，点击顶部「搜索」或按Ctrl+F可再次打开。

搜索按原字符匹配，不解释正则表达式；默认忽略大小写，全词匹配要求目标两侧不能紧邻字母、数字或下划线。范围为当前接收区保留的显示内容，包括当前可见的发送记录和系统提示；文本/HEX、编码等显示选项变化或日志裁剪后会重新匹配。新接收内容使用增量匹配，目标跨多次接收也可识别；大量高亮分批处理，保留界面响应。搜索词和匹配选项只在当前会话中保留。

在接收区用鼠标框选字符后按 **Ctrl+F**，会先读取选区，再打开并聚焦搜索输入框，以原选区字符立即匹配已有接收内容。中文、空格及正则符号均按原样搜索；大小写和全词开关继续生效。没有选区时只打开搜索框，保留现有搜索词。

「样式 → 字体样式」打开字体对话框，提供宋体、楷体、隶书等常用中文字体、常用英文字体及本机字体；默认宋体、常规、13号、黑色。字形可选常规、粗体、斜体、粗斜体，字号范围6～48。「选择颜色…」打开系统颜色选择器，可从色谱选色；预览即时更新，点击「确认」应用，点击「取消」保留原设置。「App样式」暂为空占位。

V1.19不再使用Treeview作为指令表的底层控件。表头、正文、勾选框、发送按钮和分隔线全部由一块Canvas绘制，数据模型管理选择和滚动，仅绘制可见行。画布是扩展栏内视口的子控件，靠右固定，由父视口裁剪；已移除工作区覆盖层和动态窗口区域。这样不会出现底层Treeview与画布同时显示指令，也不会让表格覆盖接收区。单击指令或间隔时复用一个真实Entry，双击指令打开完整编辑框。500条数据不对应500组控件，无效间隔草稿在滚动、隐藏列及调整宽度时保留。

Windows下每次应用最新拖动位置时，将工作区与已显示子控件的更新合在同一个同步回调中，完成布局、可见行绘制后恢复呈现；不会跨回调禁用重绘，也不等到松开鼠标。子控件改变位置或尺寸时禁用旧客户区像素的自动复制，更新后重绘暴露区域，避免复制旧布局留下重影。实时效果仍取决于屏幕刷新率和系统负载。实现参考 [WM_SETREDRAW](https://learn.microsoft.com/en-us/windows/win32/gdi/wm-setredraw) 与 [SetWindowPos](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwindowpos)。

串口继续使用后台线程和队列；接收区批量插入显示。拖动期间每轮队列处理预算从12毫秒降至4毫秒，存在积压时留出4毫秒再继续处理。搜索仍分批高亮，搜索条移动或关闭时同时更新旧、新位置的暴露区域，清除旧位置残留。

仅在主窗口确实改变尺寸的短暂过渡期间，先按控件底色填充待绘制区域，再由Tk绘制文字和控件，避免系统动画展示未填充的黑块。窗口动画维持系统行为。原生回调只调用Win32/GDI，底色在界面线程缓存，窗口销毁前移除回调；实现依据 [Tk的Windows子窗口消息实现](https://github.com/tcltk/tk/blob/core-8-6-branch/win/tkWinX.c)、[Microsoft WM_ERASEBKGND 文档](https://learn.microsoft.com/en-us/windows/win32/winmsg/wm-erasebkgnd)和 [SetWindowSubclass 文档](https://learn.microsoft.com/en-us/windows/win32/api/commctrl/nf-commctrl-setwindowsubclass)。主窗口尺寸或状态改变且稳定60毫秒后，再合并请求窗口及子控件重绘；仅移动窗口或扩展内部滚动不会触发整窗刷新，使用的标志依据 [Microsoft RedrawWindow 文档](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-redrawwindow)。

全局参数自动保存不包含预设列表。指令表使用扩展的「保存」按钮保存至独立指令表库，也可导入/导出单表。读取参数配置后优先恢复已保存指令表库；没有表库时加载原配置预设或默认模板。启动、修改输入和定时运行均不会立即写入全局参数，主发送或退出时统一保存。

## 编码的作用

发送工作区的「编码」决定发送文本到字节的转换；接收区的「显示格式」独立决定收到的字节如何解码，两项均应按设备协议选择。

| 编码 | 适用情况 |
| --- | --- |
| UTF-8 | 设备按 UTF-8 收发文本，可表示中文及多种语言字符。 |
| ASCII | 英文字母、数字、标点等 7 位 ASCII 字符，不支持中文。 |
| GBK | 设备按 GBK 收发的中文文本。 |

例如 `A00 GET VER INF` 全部由 ASCII 字符组成，选 UTF-8、ASCII 或 GBK，发送字节都相同。中文「中」则不同：UTF-8 为 `E4 B8 AD`，GBK 为 `D6 D0`。选择 ASCII 编码发送中文时会提示无法表示该字符，避免静默替换。

文本发送和勾选 / 取消「以HEX发送」时的文本转换使用发送工作区的「编码」。文本接收使用接收区的「显示格式」；切换显示格式会重新解释保留的接收历史，改变发送编码不影响接收解码。紫色 `#8000ff` 的发送回显按发送编码显示。处于 HEX 发送模式时，输入的十六进制码值直接决定实际字节，例如 `AA 55` 就发送这两个字节；「HEX 显示」直接展示原始字节，不依赖文本编码。波特率、数据位和校验位分别由串口参数控制。

程序内也可通过「帮助 → 编码说明」查看。

## 打包 EXE

本机已有 PyInstaller，可以双击 `build_exe.bat`。构建脚本仅使用本地依赖，不自动安装、不联网，也不递归删除整个构建目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1
```

文件名从 `src/sscom_tool/__init__.py` 中的 `APP_TITLE` 自动读取，本版产物为 `dist\SSCOM_TOOL_V1.21.exe`，可双击运行。后续版本随标题版本自动变化。首次在其他开发电脑打包前，需自行准备 PyInstaller：

```powershell
.\.venv\Scripts\python.exe -m pip install pyinstaller
```

最终EXE由用户执行打包。旧EXE仍在运行时Windows不允许覆盖同名文件；也可用以下命令指定其他名称，`verify.ps1`和`tests\exe_smoke.ps1`支持同名参数：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -ExecutableName SSCOM_TOOL_V1.21
```

只核对将要生成的名称、不执行打包：`build_exe.bat -NameOnly`。

### 真实硬件收发验证

2026-11-10 使用应用自身的 `SerialService` 通信模块，在 **USB-SERIAL CH340（COM101）、57600、8N1、无流控、DTR / RTS 关闭** 条件下实测通过：

```text
TX（17 字节）：A00 GET VER INF\r\n
RX（34 字节）：MAIN MCU V0.04 \r\nAUX  MCU V0.00 \r\n
```

实际返回与预期逐字节一致，包括两行行尾的空格、`AUX` 后的两个空格，以及 CRLF；没有丢弃字节，测试结束后已释放串口。原始 HEX、每次读取的字节数和时间记录在 `artifacts/hardware-com101-20261110-173328.json`。这是首次通信模块实测记录。

复测前先关闭其他程序对 COM101 的连接，再执行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\hardware_test.ps1 -Port COM101 -BaudRate 57600
```

此脚本仅发送上述版本查询一次，不调用其他设备命令。图形界面测试时，在发送区填写 `A00 GET VER INF`，结束符选择 `CRLF`；不要把字面的 `\r\n` 也填入文本输入框。

同日已完成真实窗口端到端测试：COM101、57600、8N1，仍发送 17 字节并接收 34 字节。设备当时返回 `MAIN MCU V1.02 \r\nAUX  MCU V0.00 \r\n`，读取分段为 **1、31、1、1 字节**。窗口显示与原始字节对应的文本完全一致，没有拆开 `MAIN`，没有由分段 CRLF 产生空行，发送为 `#555555` 深灰色、接收为 `#000000` 黑色；测试后已释放串口。详细记录：`artifacts/hardware-gui-com101-20261110-195143.json`。

真实窗口复测：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\hardware_test.ps1 -Port COM101 -BaudRate 57600 -Gui
```

通信模块脚本固定核对首次提供的 V0.04 预期；界面测试按设备当前的版本返回核对显示，并单独记录是否与首次版本一致。

接收字符按连续字节流追加，读取批次不代表协议帧，也不会导致换行。文本模式按设备实际发送的 CR / LF 换行，跨读取拆开的 CRLF 只换一行；「HEX 显示」将收到的字节显示成 ASCII 十六进制码值，保留 `0D 0A` 两个码值并在其后换行，例如 `41 0D 0A\n42 0D 0A\n`，即使 CR 和 LF 分两次读到也能正确换行。时间戳每行显示一次，HEX 字节以空格分隔。收发记录不带 `RX ←` 或 `TX →` 前缀，通过黑色 / 紫色区分；导出纯文本日志不保留颜色。

切换 HEX / 文本会立即重绘已有收发数据，取消勾选可还原；系统提示文字保留可读形式。切换编码、时间戳或显示发送选项，也会更新保留的历史。字号调整只改变显示大小，保留内容和字节。

窗口最多保留约 50 万个显示字符，重绘使用的历史缓存上限为约 2 MiB 或 65536 条记录，较早内容会裁剪。导出日志保存当前窗口历史；历史裁剪与尚待显示的接收积压是两个独立过程。

旧实现将接收队列限制为 256 次读取事件，界面每 30 ms 最多取出 128 项。一字节的小片段和大段数据各占一项，因此密集小片段、突发数据或界面暂时忙碌均可能导致队列满；旧提示中的「941 B 未显示」是程序已收到但为显示而排队时丢弃的字节数，不代表串口总共只收到这些字节，也不能据此判断硬件已经丢包。

当前实现合并相邻接收片段，按字节量缓存，最多约 1 MiB 待显示原始字节保留在内存，其余积压暂存程序目录下的 `sscom_rx_*.tmp` 临时文件。界面按时间及字节预算批量刷新，有积压时更快续取，状态栏显示「待显示 N B」；不再因超过 256 个片段直接丢弃数据。临时文件在对应积压读完后释放。若临时文件读写失败，会明确报错并计数，不能将磁盘故障视为正常积压。该缓存用于补显示，并非无限时长原始数据录制；关闭 APP 会结束尚未处理的数据，完整长时采集仍需专门的数据记录功能。

TX 计数表示成功交给驱动的字节数，不代表设备已确认；若驱动写入超时，可能已有部分数据发出，程序会报错、停止自动发送并等待设备恢复，不会重新发送失败指令或旧队列。自定义波特率与 DTR / RTS 的具体行为由驱动和硬件支持情况决定。
